## 三、主攻方向（P0 之后三选一或并行）

### 方向 A：内容搜索 —— 补齐网盘基线的最后一块

**现状**：搜索只有 `filename ILIKE '%q%'`（`internal/api/v2/files/handler.go:1297`），
无法走索引，也搜不到文件内容。这是与百度/阿里"同台比较"的必要条件。

**任务分解**

| 编号 | 任务 | 说明 |
|---|---|---|
| A1 | `search_index` 表 + GIN 索引 | 单表存 `tsvector`，字段来源见 A2；也可用 `file_items.search_vector` 列 |
| A2 | 索引源接入 | 文件名/原始名/描述/标签/评论（**已有数据**）+ 转写文本（`transcription_tasks.content` **已有**）+ OCR 文本（待 C2） |
| A3 | 增量维护 | 上传、改名、打标签、加评论、转写完成 → UPSERT 索引 |
| A4 | 查询端点升级 | `GET /files/search` 支持相关性排序 + 过滤（类型/时间/大小/标签/分类） |
| A5 | 前端搜索页 | 筛选器 + 命中高亮 + 「搜索内容」与「仅文件名」切换 |
| A6 | （后续）语义搜索 | `pgvector` + 本地嵌入模型，与 A1 同表不同列 |

**验收**：10 万文件下 P95 < 200 ms；搜「合同」能同时命中文件名、标签、评论与字幕文本。

**估算**：A1–A5 约 8–12 人日（A6 单列 8–10）。

---

### 方向 B：同步客户端 —— 个人用户"回不去"的核心

**现状**：服务端 API 全部就绪（`/sync/changes`、`/sync/upload`、`/sync/upload/assign`、
`/sync/upload/session`），**没有任何客户端**。`docs/windows-app-guide.md` 已存在但只是计划。

**里程碑**

| 编号 | 里程碑 | 内容 | 验收 |
|---|---|---|---|
| B1 | M1 只读镜像 | Go + SQLite 本地状态 + `fsnotify`；服务端变更单向下载、本地变更单向上传 | 1 万文件首同步完成；变更 500 ms 内触发 |
| B2 | M2 双向同步 | 冲突策略：保留双方并重命名 | 断网 10 分钟后恢复，无数据丢失 |
| B3 | M3 选择性同步 | 占位文件（Windows CFAPI / macOS FileProvider，退化实现为占位文件） | 用户可只同步部分目录 |
| B4 | 打包与托盘 | Windows MSI（后续 macOS 签名+公证） | 无管理员权限可安装 |

**技术选型**：Go（与本仓库同语言，可复用 `pkg/storage` 的哈希与 `ObjectKey` 约定）。

**风险**：文件系统监听的边界（大量小文件、重命名风暴）、Windows 路径与长路径、
冲突策略的语义要让用户看得懂。

**估算**：B1 6–8；B2 5–7；B3 5–7；B4 3–5。**合计 19–27 人日**，是当前最大的一块。

---

### 方向 C：自托管独有的纵深（护城河）

| 编号 | 任务 | 为什么只有自托管能做 | 估算 |
|---|---|---|---|
| C1 | 真 E2EE 私密空间 | 现在 `vault` 是**服务端持钥**的 AES-256-GCM；改为客户端派生密钥 + 分块加密后，服务端也解不开 | 10–15 |
| C2 | 本地 AI 套件 | OCR → 喂 A2；自动标签；照片场景/人脸聚类。**数据不出内网**，商业网盘必须上传云端 | 15–25（可分步） |
| C3 | 局域网快传 | 同网段直连，不经服务器；对应阿里云盘"快传" | 8–12 |

> C1 若与 A（搜索）同时进行会冲突：E2EE 的内容无法被服务端索引。需要明确"私密空间不参与内容搜索"的产品语义。

## 四、推荐路径

```
P0 收尾（F1–F6，6–8 人日）   ← 让当前成果可部署、可验证
        │
        ├─► B1 同步客户端 M1（6–8 人日）   ← 个人用户体验的分水岭，服务端已就绪，投产比最高
        │        └─► B2 → B3 → B4
        │
        └─► A 内容搜索（8–12 人日，可与 B1 并行）
                 └─► A6 语义搜索（依赖 C2 的 OCR/嵌入）
```

**为什么先 B 后 A**：目标用户是个人/家庭。搜索是"有更好"，同步客户端是"没有就不算网盘"；
而 B 的服务端部分已经全部就绪，边际成本最低。

**如果只有一个人在做**：P0 → B1 → A1–A4。C 与 D 往后放。

## 五、明确不做（以及为什么）

| 项 | 原因 |
|---|---|
| CRDT 实时协作 | 与已有的 WOPI/Collabora 在线编辑功能重叠，20–30 人日换来的增量体验最小 |
| PDF 首页缩略图 | 需要引入 poppler，收益低于成本（现用文件图标兜底） |
| 多租户 / 计费 / 订阅 | 与"自托管、无会员墙"的定位冲突 |
| 移动端原生 App | Web 与 WebDAV 已覆盖大部分场景；等同步客户端验证了需求再评估 |
| MinIO 适配 | 已归档且转向 AGPL 独占，明确不再支持（见 `docs/deployment-rustfs.md`） |
